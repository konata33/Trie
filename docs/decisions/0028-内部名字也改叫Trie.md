# 0028 内部名字也改叫 Trie

- 状态：采用
- 日期：2026-11-12

## 背景

[0021](0021-应用名叫Trie.md) 把应用名改成了 Trie，但代码、目录和环境变量里还叫 BlogShelf。从源码运行时，Dock 上悬停显示的仍是 blogshelf。新版换上真实资料库以后（[0027](0027-新版换上真实资料库.md)），维护者要求把 BlogShelf 彻底去掉。

## 决定

维护者定的：BlogShelf 这个名字从代码、资料库目录和两个应用里全部去掉，统一改叫 Trie。

- 新版的 Go 模块叫 `trie`。从源码运行时，Dock 上显示 trie。
- 环境变量都以 `TRIE_` 开头，例如 `TRIE_DATA_DIR`。
- 资料库目录是 `~/Library/Application Support/Trie`，备份目录是 `~/Library/Application Support/Trie Backups`。
- 新版的 bundle identifier 是 `com.example.trie`。两版发给网站的 User-Agent 都是 `Trie/0.1`。
- 旧版也跟着改名，它的界面协议改成 `trie://`。旧版的资料库目录跟着它的应用名走，两版又要共用一份资料，所以旧版必须一起改。

## 考虑过的其他做法

- **只改 Go 模块名，资料库目录不动**：没选。要求是彻底去掉。
- **新版启动时自动把旧目录搬过去**：没选，有两个问题：
  - 旧版一启动就会新建一个空目录。两版谁先启动，结果就不一样。
  - 代码里还得留着旧名字。

  趁两个应用都关着，手动搬一次，最简单。
- **旧版继续用旧目录**：没选。两版就不再共用一份资料，退回旧版时看到的是旧数据。

## 影响

- 资料库目录只搬一次，搬的时候两个应用都关着，搬之前先完整备份。2026-11-12 已经搬完。
  - 搬之前的备份在 `~/Library/Application Support/Trie Backups/2026-11-12-1809-before-rename`。
  - 备份、原库和搬过去的库，各表条数都核对过，一致。
- 新版换了 bundle identifier，macOS 把它当成一个新应用。当时 Dock 上没有固定 Trie，也没有存偏好设置，所以没有东西要迁过去。
- 以下几处讲来历的地方仍写着 BlogShelf：0021、0027 和这一份决策记录，以及 `.context` 里的旧草稿和脚本。
- 还叫 blogshelf 的几处都不在代码里，改不改由维护者决定：
  - GitHub 上的仓库名。
  - Conductor 里的项目名。
  - 本机的仓库目录。
