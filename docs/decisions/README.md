# 决策记录

这里记 Trie 的设计和产品决定：为什么这样定，考虑过哪些做法，带来什么影响。规范（[docs/](../) 下的 PRODUCT.md、DESIGN.md、PAGES.md、READER_ENGINE.md）只写现在怎么做；想知道一条规则为什么是这样、哪些做法已经否掉，来这里查。

## 什么时候写一份

- 定下或推翻一条规则，并且有过取舍：比较过几种做法，或者否掉了一种。
- 由维护者拍板的决定，在「决定」里写明。
- 只是实现上的限制（比如界面框架不支持某种写法）不单独写，放进相关决定的「影响」里。
- 一个决定一份。决定被推翻时另写一份，把旧的那份状态改成「已被取代」并链到新的。

## 文件名

`NNNN-短标题.md`：四位编号，按先后递增，不复用，例如 `0005-换页移焦.md`。

## 每份怎么写

```
# NNNN 标题

- 状态：采用
- 日期：YYYY-MM-DD

## 背景
## 决定
## 考虑过的其他做法
## 影响
```

- 背景：当时的情况和要解决的问题。
- 决定：定了什么、谁定的。细则写「见 DESIGN.md 某一节」，不抄规范原文。
- 考虑过的其他做法：每种一句为什么没选。
- 影响：这个决定带来的后果和限制。
- 中文，简短、平实。

## 状态

只用三种：

- 采用：现在照这个做。
- 已被取代：被后来的决定换掉，写成「已被取代，见 [NNNN](NNNN-短标题.md)」，链到取代它的那份。
- 废弃：不再适用，也没有替代。
