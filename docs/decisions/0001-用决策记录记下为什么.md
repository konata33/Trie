# 0001 用决策记录记下为什么

- 状态：采用
- 日期：2026-11-10

## 背景

规范里原来混着日期、「维护者定」标注、维护者的原话、试过又否掉的做法和代码细节。旧约定是：新决定写进规范对应的那一节，带日期；维护者定的写明「维护者定」；被否掉的做法留一句「试过什么、为什么否」。2026-11-10 维护者要求：规范是使用说明，不是备忘录。

## 决定

规范（DESIGN.md、PAGES.md 等）只写现在的做法：陈述句、具体数值，不写日期、来历、被否的方案、代码名和实现细节。为什么这样定、考虑过哪些做法，写进本目录，一个决定一份，格式见 [README](README.md)。

## 考虑过的其他做法

- 来历照旧写在规范里：没选，这正是要改掉的写法。

## 影响

- 改写规范时删下来的来历，补写成 0002–0017，编号按当时做决定的日期排。
- 规范里不再标「维护者定」；哪条由维护者决定，写在对应记录的「决定」里。
- 纯实现上的限制不单独成文，写进相关决定的「影响」，或者留在代码注释里。
